## 📌 Resumen Ejecutivo

KIN Platform libera **`v2.0.0-phase10`**, el hito que **sanciona el Bounded Context Enterprise**
(ADR-018): generación, versionado, persistencia y exportación de documentos de negocio de un
proyecto KIN (lean canvas, plan de mercado, plan financiero, hoja de ruta, matriz de riesgos,
KPIs, plan de innovación, Executive Report y DOFA) en formatos PDF/DOCX/PPTX, consumiendo el
`ProjectContext` durable y los resultados reales del pipeline.

La release también corrige la **brecha de esquema de suscripciones** (V9/V10): `users.current_plan_id`
y la tabla `user_subscriptions` que el commit `44edbf4` (sistema de planes) introdujo en las
entidades sin migración, causando el fallo de login `column u1_0.current_plan_id does not exist`
en PostgreSQL. Dev (H2, `ddl-auto: update`) lo enmascaraba; producción (PostgreSQL, `ddl-auto: none`)
lo exponía.

Principio rector (intacto):

> **Java decide. El LLM únicamente comunica.**
> Java decide qué documentos generar, en qué orden y con qué datos del pipeline; el LLM solo
> redacta la narrativa del Executive Report (M3E) con fallback determinista.

## ✨ Novedades

- **Bounded Context Enterprise** (`com.kinplatform.kin.enterprise`, dominio POJO sin Spring):
  - Aggregate `EnterpriseProject` con máquina de estados `REQUESTED → RUNNING → COMPLETED | FAILED`
    y versionado compuesto `(projectId, version)`.
  - 20+ value objects con invariantes (`LeanCanvas`, `MarketPlan`, `FinancialPlan`, `Roadmap`,
    `RiskMatrix`, `KpiSet`, `InnovationPlan`, `EnterpriseScore`, etc.).
  - **8 motores deterministas puros** (`DefaultMarketEngine`, `DefaultFinancialPlanEngine`,
    `DefaultRoadmapEngine`, `DefaultKpiEngine`, `DefaultRiskPlanEngine`, `DefaultInnovationEngine`,
    `DefaultBusinessModelEngine`, `DefaultEnterpriseScoreEngine`) — aislados deliberadamente de
    `EngineRegistry` (no son etapas del pipeline).
  - **9 tipos de documento**: LEAN_CANVAS, MARKET_PLAN, FINANCIAL_PLAN, ROADMAP, RISK_MATRIX, KPIS,
    INNOVATION_PLAN, EXECUTIVE_REPORT y DOFA.
- **Narrativa IA (M3E)**: `EnterpriseNarrativeGenerator` invoca `AIResponder` (puerto de dominio,
  ADR-008) para el Executive Report; extensión **aditiva** de `PromptType`/`PromptAssembler` sin
  violar la frontera ADR-012 (REPORT sigue consumiendo solo `ConsultingReport`).
- **Ciclo automático (M3B)**: `ConversationOrchestrator` (constructor aditivo de 6 args) dispara
  `EnterpriseProjectTrigger → DomainEventBus → EnterpriseProjectRequestedListener → generación
  asíncrona` (pool dedicado) al completar un turno `REPORT`.
- **Resultados reales del pipeline (M3C)**: `KinMethod` publica los 4 resultados deterministas del
  turno (recomendaciones, riesgos, oportunidades, conocimiento) en `EnterprisePipelineResultStore`;
  el listener los fusiona en la `EnterpriseGenerationRequest` (modo offline-first si no hay turno previo).
- **Enterprise Score (M3D)**: 8 dimensiones + grado, persistido en `enterprise_project` (`@Embedded`)
  y expuesto en dashboard/latest/versión.
- **UI (M3F/M3G)**: dashboard enterprise dentro de `kin-frontend` con SSE de progreso
  (`/enterprise/{projectId}/{version}/stream`) y botón de generación con refetch automático.
- **Fix de esquema (V9/V10)**: `users.current_plan_id` + tabla `user_subscriptions` creadas por
  Flyway; el login en PostgreSQL ya no falla y las suscripciones/límites por plan funcionan.

## 🏗️ Arquitectura

```
Usuario → ChatController → ConversationOrchestrator → KinMethod →
Pipeline (13 etapas: Analizador → Evaluador → Estratega → Entrevista → Conocimiento →
Enriquecimiento → Scoring → Recomendaciones → Riesgos → Oportunidades → Reporte → Consultor → Eventos)
→ ConsultingReport (11 secciones)
  → turno REPORT → EnterpriseProjectTrigger → DomainEventBus → listener → generación asíncrona
  → EnterpriseProject (versionado) → documentos (PDF/DOCX/PPTX)
```

- **Clean Architecture + DDD Táctico + Pipeline Pattern + Event-Driven**.
- El BC Enterprise es **aditivo**: no se registró ningún motor Enterprise como `DomainEngine` y el
  runtime conversacional sigue siendo la única entrada de la generación.
- Frontend Next.js 16 con Enterprise Dashboard integrado (misma sesión/origin, sin CORS extra).

## ⚠️ Breaking Changes

- **`kin-enterprise-ui` (standalone Vite) eliminado** — sustituido por el Enterprise Dashboard
  integrado en `kin-frontend` (M3F). No hay ruta de UI alternativa en `:5173`.
- **`pricing_plans.features` es `jsonb` en PostgreSQL** (V8) — el mapeo de la entidad usa
  `@JdbcTypeCode(SqlTypes.JSON)`; los inserts manuales con texto no-JSON fallan (comportamiento
  deseado).
- **Esquema de suscripciones (V9/V10)**: cualquier instalación PostgreSQL previa a estas migraciones
  debe aplicarlas para que login y suscripciones funcionen.
- Ningún contrato congelado del `BASELINE_ARCHITECTURE.md` fue modificado.
