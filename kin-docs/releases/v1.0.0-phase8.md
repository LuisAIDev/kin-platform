## 📌 Resumen

KIN Platform alcanza su **primera release estable** (`v1.0.0-phase8`) con la **Fase 8
(Knowledge-Enhanced Analysis) cerrada oficialmente**. La plataforma valida proyectos desde la
idea hasta el informe de viabilidad con **conocimiento externo verificado y fuentes citadas**,
guiada por el principio arquitectónico:

> **Java decide. El LLM únicamente comunica.**

La release integra de extremo a extremo: adquisición de conocimiento externo (Fase 6),
entrevista estratégica (Fase 7) y enriquecimiento del análisis con hechos verificados que se
citan en el `ConsultingReport` (Fase 8), sobre un **pipeline de 13 etapas**.

---

## ✨ Novedades

- **EnrichmentEngine** (`com.kinplatform.kin.enrichment`, ADR-016): motor canonizado
  (`DomainEngine`, fase `ANALYSIS`, prioridad 55) que selecciona y pondera en Java los hechos
  externos relevantes por categoría mediante `FactRanker` (score por `SourceTrust`, frescura y
  cobertura semántica; determinista, sin LLM).
- **EnrichmentStage** en el pipeline: nueva etapa aditiva entre `KnowledgeStage` y `ScoringStage`
  (pipeline de **13 etapas**), que escribe `PipelineContext.enrichmentResult`.
- **Inputs aditivos en los motores de análisis**: `RecommendationInput`, `RiskInput`,
  `OpportunityInput` y `ReportInput` ganan `.withEnrichment(...)`; los analizadores de mercado,
  innovación, financiero y competitivo incorporan los hechos como evidencia. Constructores
  originales intactos.
- **SourcesSection** (11.ª sección del `ConsultingReport`): `SourcesSectionAssembler` + `CitedSource`
  deduplican y citan las fuentes; `SourcesSectionFormatter` las presenta en el prompt REPORT
  (frontera ADR-012 intacta: el prompt consume únicamente el `ConsultingReport` tipado).
- **Corrección del defecto crítico de la auditoría E7**: `ReportPromptBuilder` ahora reconoce
  `SourcesSection` y la formatea con `SourcesSectionFormatter` — sin `IllegalArgumentException`
  en reportes enriquecidos.

## 🏗️ Arquitectura

```
Usuario → Frontend (Next.js 16) → Backend (Spring Boot 3.2.5) → ConversationOrchestrator →
Pipeline de 13 etapas → Knowledge → Enrichment → Scoring → Recommendation → Risk → Opportunity
→ Report → Prompt Builder → DeepSeek LLM → Respuesta IA
```

- **Clean Architecture + DDD Táctico + Pipeline Pattern + Event-Driven**.
- Dominio puro `com.kinplatform.kin.*` (sin Spring/JPA/IA) con bounded contexts:
  `engine`, `pipeline`, `context`, `scoring`, `reporting`, `ai`/`ai.prompt`, `conversation`,
  `knowledge`, `interview` y `enrichment`.
- **16 ADRs aprobadas** (ADR-001 … ADR-016). Contratos congelados del
  `BASELINE_ARCHITECTURE.md` intactos — todos los cambios de la Fase 8 son aditivos sancionados.
- **Offline First**: sin hechos externos, `EnrichmentResult.empty()` y el pipeline se comporta
  exactamente como antes.

## 🔄 Compatibilidad

- **Backward compatible**: todos los cambios son aditivos; ningún contrato congelado del baseline
  se modificó (solo aditivos sancionados por ADR-016).
- **Offline-first**: sin fuentes de conocimiento configuradas, la plataforma funciona igual que
  en releases anteriores (fallback en español, `EnrichmentResult.empty()`).
- **API REST estable**: todos los endpoints bajo `/api/v1`, incluyendo `/chat/stream` (SSE).
- **Base de datos**: H2 (dev, `ddl-auto: update`) y PostgreSQL 16 (prod, Flyway V1…V5) sin cambios.
- Dev sin Docker; Docker Compose para producción.
