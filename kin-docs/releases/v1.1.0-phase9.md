## 📌 Resumen Ejecutivo

KIN Platform libera **`v1.1.0-phase9`** (KIN 2.1 — "Pipeline Estabilizado"), el hito que **estabiliza
el pipeline de 13 etapas**: resiliencia por stage (retry, timeout, métricas, error handling),
semántica completa de eventos, consumo real de la validación de respuesta con fallback
determinista y una integración end-to-end verificada. Cierra el roadmap documentado en
`ARQUITECTURA_BASE_KIN_2.0.md` §9 y sanciona el cambio con **ADR-017 (Aprobado)**.

Principio rector (intacto):

> **Java decide. El LLM únicamente comunica.**
> Java decide políticas de reintento/fallo, timeout, métricas, semántica de eventos y el contenido
> del fallback de respuesta; el LLM solo comunica.

## 🏗️ Arquitectura

```
Usuario → ChatController → ConversationOrchestrator → KinMethod →
Pipeline (13 etapas) → Knowledge → Enrichment → Scoring → Recommendation → Risk →
Opportunity → Report → Consultor → Response Validation → Response Fallback → Respuesta Final
```

- **Clean Architecture + DDD Táctico + Pipeline Pattern + Event-Driven**.
- Nuevo bounded context `com.kinplatform.kin.pipeline.resilience` (dominio POJO, sin Spring/JPA/IA).
- **17 ADRs aprobadas** (ADR-001 … ADR-017). Contratos congelados del `BASELINE_ARCHITECTURE.md`
  intactos — todos los cambios son aditivos sancionados.
- **Offline First**: sin reintentos configurados, el pipeline se comporta exactamente como antes.

## 🔄 Compatibilidad

- **Backward compatible**: todos los cambios son aditivos; ningún contrato congelado se modificó.
- **Constructores históricos intactos**: `ConversationOrchestrator`, `ConsultorStage`, `KinMethod`
  conservan sus constructores y ganan overloads aditivos con `ResponseFallback`.
- **API REST y SSE intactos**: endpoints bajo `/api/v1` y el contrato `token`/`error`/`done` sin cambios.
- **Base de datos**: H2 (dev) y PostgreSQL 16 (prod, Flyway V1…V5) sin cambios.
- **Offline-first**: sin reintentos configurados, comportamiento idéntico al previo.

---

## 🛡️ Riesgos corregidos

- **`ResponseValidation` era un artefacto de auditoría** (BASELINE §7.5 Prioridad 2): ahora se
  consume en bloqueante y streaming con fallback/reintento determinista.
- **`EventStage` no cubría la semántica completa de eventos** (riesgo R2 del baseline): ahora emite
  los eventos correctos según decisión y flujo real, incluido `risk_detected`.
- **Pipeline sin resiliencia** (KIN 2.1): errores, timeouts y métricas por stage controlados.

## ⚡ Rendimiento

- Métricas internas sin persistir ni exponer (sin Micrometer/Actuator); overhead mínimo.
- Timeout por stage medido de forma síncrona con solo Java 17 (sin infraestructura externa).
- Default conservador sin reintentos; backoff (`NONE`/`FIXED`/`EXPONENTIAL`) solo cuando la
  política lo permite.
