# ADR-043: Motor RIPS — Arquitectura de Generadores y Serialización

## Contexto
KIN Billing genera seis tipos de registro RIPS (US, AF, AC, AP, AU, AT) a partir
de datos clínicos (pacientes, encuentros, órdenes) y contractuales (EPS, tarifas
CUPS). Cada tipo tiene estructura, reglas y campos distintos, y debe producirse
como línea JSON auditable (`rips_line_data`) asociada a un batch.

Durante la construcción del motor se detectó un defecto crítico: los generadores
AC y AP construían un `ObjectMapper` nuevo sin `JavaTimeModule`. La serialización
de `LocalDate` lanzaba `InvalidDefinitionException`, el `catch` devolvía `"{}"` y
las líneas RIPS de consultas y procedimientos se enviaban **vacías** (≈80% del
volumen), con riesgo de rechazo masivo de la facturación.

## Decisión

### 1. Un generador por tipo RIPS
`RipsGenerator` define `generate(context)` y `supports(type)`. Se implementan
`UsGenerator`, `AfGenerator`, `AcGenerator`, `ApGenerator`, `AuGenerator`,
`AtGenerator`. `RipsGenerationOrchestrator` resuelve idempotencia por
(organización, contrato, período, tipo) y persiste `RipsBatch` + `RipsRecord`.

### 2. Separación de responsabilidades de persistencia
- `RipsBatch` y `RipsRecord` son entidades JPA (única vía de persistencia).
- Las clases de línea (`UsRecord`, `AfRecord`, `AcRecord`, `ApRecord`,
  `AuRecord`, `AtRecord`) construyen el contenido vía factories estáticos
  (`AfRecord.fromContract`, `AuRecord.fromEncounter`, `AtRecord.fromOrder`,
  etc.) usando `.builder()`.

### 3. ObjectMapper de Spring inyectado
Toda serialización JSON en los generadores usa el `ObjectMapper` gestionado por
Spring (con `JavaTimeModule` y `write-dates-as-timestamps: false`), nunca
`new ObjectMapper()` local. Fechas en ISO-8601 (`yyyy-MM-dd`).

### 4. Falla ruidosa
Se elimina el `catch` silencioso. Ante un fallo de serialización se lanza
`RipsSerializationException` (no se devuelve `"{}"`).

```java
private String buildAcJsonLine(...) {
    try {
        return objectMapper.writeValueAsString(ac);
    } catch (JsonProcessingException e) {
        throw new RipsSerializationException("No se pudo serializar AC: " + e.getMessage(), e);
    }
}
```

### 5. Build: sin plugin de doble pasada
Se eliminó un `maven-compiler-plugin` con `<proc>none</proc>` que desactivaba
Lombok en la compilación principal (causaba 200 `cannot find symbol`). Se usa el
plugin por defecto del `spring-boot-starter-parent`.

## Consecuencias

### Positivas
- AC/AP ya no producen líneas vacías; el 80% del volumen RIPS se preserva.
- Fechas ISO-8601 consistentes en todas las líneas.
- Los fallos de serialización son visibles y detienen el batch.
- Compilación 1098 archivos OK; errores de test 48 → 34.

### Negativas
- Los generadores dependen del `ObjectMapper` de Spring (requiere contexto en
  integración; en unit tests se inyecta uno equivalente configurado).

## Validación
- `AcGeneratorTest` / `ApGeneratorTest`: `ripsLineData` nunca `"{}"` y contiene
  patrón ISO-8601 (`\d{4}-\d{2}-\d{2}`).
- 23 tests de generadores PASS.
