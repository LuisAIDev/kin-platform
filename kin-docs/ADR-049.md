# ADR-049: Roles IPS_* y Modelo Multi-Sede

## Contexto
KIN nació como plataforma para médicos independientes. Para venderlo a IPS y
clínicas se requiere una fundación institucional: roles por función dentro de la
IPS, sedes y equipos médicos, sin romper el modelo de personas/verticales ya
existente (Sprint 1).

## Decisión

### 1. Roles institucionales en `UserRole`
Se añaden al enum (y al CHECK de `users`):
`IPS_ADMIN`, `IPS_MEDICO`, `IPS_ENFERMERA`, `IPS_FACTURADOR`, `IPS_AUDITOR`.

- El constraint real es `users_role_check` (creado en V40); se recrea en V62
  manteniendo `FACILITADOR` para no romper filas existentes.
- `JwtAuthenticationFilter` deriva `ROLE_<role>` automáticamente; no hay
  `switch` exhaustivo sobre `UserRole`, así que la extensión es no-breaking.

### 2. Sedes (`Branch`)
Entidad `Branch` (tabla `institutional_branches`): `organization_id`, `name`,
`address`, `phone`, `city`, `services_enabled` (JSONB). Único por
`(organization_id, name)`.

### 3. Miembros del equipo (`OrganizationMember`)
Entidad `OrganizationMember` (tabla `organization_members`): `organization_id`,
`user_id`, `branch_id`, `role` (UserRole IPS_*), `status`
(`INVITED`/`ACTIVE`/`REMOVED`), `invited_at`, `joined_at`. Único por
`(organization_id, user_id)`.

### 4. Seguridad
Reglas en `SecurityConfig` (recordar: `context-path=/api/v1`, los matchers NO
llevan `/api/v1`):
- `POST /institutional/inquiries` → público (lead landing).
- `/institutional/admin/**` → `IPS_ADMIN`, `ADMIN`.
- `/institutional/facturacion/**` → `IPS_FACTURADOR`, `IPS_ADMIN`, `ADMIN`.
- `/institutional/**` → cualquier rol IPS_* o `ADMIN`.

### 5. Multi-tenant
Todas las queries filtran por `TenantContext.get()` (`organization_id`).

## Consecuencias
### Positivas
- Base para vender a IPS: sedes + equipos + acceso por función.
- Compatible con Sprint 1 (roles existentes intactos).
- Frontend institucional (`/dashboard/institutional/**`) listo.

### Negativas
- Los roles IPS_* aún no se asignan automáticamente por invitación de usuario
  (se provee `user_id`); falta flujo de invitación por email.
- Falta auditoría específica por rol (`IPS_AUDITOR`).
